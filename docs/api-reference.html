Execution

Compiles a graph spec and runs it, or re-runs a graph already compiled in a previous call. Accessible as engine.execution.

execute(execution_id=None, spec=None, bucket=None, cancel_check=None)

Iterator[dict] execute(execution_id: str | None, spec: dict | None, bucket: str | None, cancel_check: Callable[[], bool] | None)

Provide spec to validate, parse, and run a new graph in one call, or pass a previously returned execution_id to re-run an already-compiled graph against a fresh context. Exactly one of execution_id and spec is required.

bucket scopes custom node types and default storage. When set, the spec is validated and compiled against that bucket's NodeRegistry (built-in types plus any custom types registered in that bucket via NodeLibrary). Any node whose type binds resource_storage and accepts a bucket param (for example fetch_internal, push_internal) is given this bucket as its default automatically, unless the node's own params already set one. bucket=None uses the default bucket.
EventWhen
validatingSpec structure and node params are being checked.
parsingNodes and connections are compiled into an execution graph.
compiledCarries the new execution_id, entry node ids, and node count.
injecting_contextShared services (storage, readers, writers) are bound to nodes.
runningTraversal starts; carries total_nodes.
node_started / node_completedEmitted for every node visited, in traversal order.
leaf_reachedEmitted once per branch with no outgoing connection; carries the resulting column list and step history.
cancelledEmitted instead of completed when cancel_check reports a cancellation; carries the execution_id, processed node count, and total node count.

failedCarries the error message, error type, and, for node failures, the offending node_id and node_type.

Cancelling a run

cancel_check is an optional zero-argument callable returning a bool. When provided, execute calls it once before traversal starts and again before every node in the graph, in order:

  • Before injecting context, right after the graph is resolved (whether just compiled or recalled via execution_id). If it returns truthy here, no node ever runs.
  • Before each step of graph.traverse(...), so cancellation takes effect between nodes rather than mid-node.

The first truthy check yields a single cancelled event and returns, without yielding completed. Either way, a cancelled execution's compiled graph is dropped from the cache, so its execution_id can no longer be reused with execute(execution_id=...).

# typical wiring: a threading.Event flipped by whatever cancels the job
cancel_event = threading.Event()

for event in engine.execution.execute(spec=spec, cancel_check=cancel_event.is_set):
    if event["event"] == "cancelled":
        break
No cancel_check, no cancellation. When it's omitted, execute runs straight through to completed or failed; the check is only ever consulted if you pass one in.

validate(spec, bucket=None)

Iterator[dict] validate(spec: dict, bucket: str | None)

Checks a spec against the registry and sandbox without compiling or running it. Yields validating followed by either valid or failed (a failed event may carry an errors list with one entry per invalid node, each with node_id, node_type, and message). bucket has the same meaning as in execute.

discard(execution_id)

None discard(execution_id: str)

Drops a compiled graph from the cache so it can no longer be reused with execute(execution_id=...). Called automatically on cancellation; can also be called directly to free a graph you know you won't re-run.

The compiled-graph cache is bounded. Execution keeps at most max_cached_graphs (default 128, set via build_engine()) compiled graphs in memory, evicted least-recently-used first. Once a graph is evicted, its execution_id can no longer be passed to execute(execution_id=...) — a fresh spec must be recompiled instead.

Data Resource

Manages the named internal resources that fetch_internal and push_internal nodes read from and write to. Accessible as engine.data_resource.

MethodParametersDescription
import_sourcekey, source_kind, source_params, bucket=None, overwrite=FalseReads from an external source (file, database, and so on) and saves the result under key.
listbucket=None, prefix=None, limit=None, offset=0Lists stored resource keys, optionally filtered by prefix and paged.
getkey, bucket=None, limit=100, offset=0Returns schema, row count, and a page of rows for a stored resource.
deletekey, bucket=NoneRemoves a stored resource.
existskey, bucket=NoneReturns a plain boolean, not an event stream.

Resources are scoped by an optional bucket, letting the same key coexist across separate namespaces.

Like Execution, every method above (except exists) yields intermediate events before a terminal completed or failed. For import_source these are, in order: validating, checking_existing, reading_source, source_read, saving, saved, counting_rows, then completed with key, bucket, columns, and row_count. import_source raises if key already exists and overwrite is not set, or if the source produces no columns.

Node Library

Registers custom node types on top of the built-in ones, so a graph can reference project-specific logic by name. Accessible as engine.node_library.

MethodParametersDescription
register_transformname, expression, description="", bucket=NoneRegisters a reusable sandboxed expression as a new transform node type. name must be a valid identifier not already used by a built-in or custom type.
unregister_nodename, bucket=NoneRemoves a previously registered custom node type. Built-in types cannot be unregistered.
get_nodename, bucket=NoneReturns the definition of one custom node type.
describe_nodesbucket=NoneReturns a descriptive summary of every node type available to the parser.
list_nodesbucket=NoneReturns built-in type keys alongside full definitions of custom types.

Custom node types are looked up by the parser the same way built-in ones are, so once registered they can be used as any other type value in a graph spec.

A node registered via register_transform takes a single required param, columns (list of string): the expression is applied to each listed column in turn and the result replaces that column in place. Inside expression, the column being processed is referenced as value rather than df.<name>. For example, registering clip_negative with expression pl.when(value < 0).then(pl.lit(0)).otherwise(value) lets a graph use:

{
  "id": "3",
  "type": "clip_negative",
  "name": "Clip Negative Amounts",
  "params": { "columns": ["amount"] }
}
