Execution

Compiles a graph spec and runs it, or re-runs a graph already compiled in a previous call. Accessible as engine.execution.

execute(execution_id=None, spec=None, bucket=None, cancel_check=None)

Iterator[dict] execute(execution_id: str | None, spec: dict | None, bucket: str | None, cancel_check: Callable[[], bool] | None)

Provide spec to validate, parse, and run a new graph in one call, or pass a previously returned execution_id to re-run an already-compiled graph against a fresh context. Exactly one of the two is required. bucket is only used when compiling from spec; it is ignored when re-running via execution_id, since the graph was already compiled against whatever bucket was active at that time.

bucket does two things. First, it selects which node registry the parser resolves type against: custom node types registered through NodeLibrary.register_transform(..., bucket=...) are only visible to graphs compiled with that same bucket (omitting it uses the default registry). A type that exists in another bucket still fails validation as an unknown node type. Second, for any node whose type binds resource_storage from context and accepts an optional bucket param (fetch_internal, push_internal), execute's bucket is copied into that node's own params.bucket whenever the spec didn't already set one. An explicit bucket in a node's params always wins over this default.

Cancelling a run

cancel_check is an optional zero-argument callable returning a bool. When provided, execute calls it once before traversal starts and again before every node in the graph, in order:

  • Before injecting context, right after the graph is resolved (whether just compiled or recalled via execution_id). If it returns truthy here, no node ever runs.
  • Before each step of graph.traverse(...), so cancellation takes effect between nodes rather than mid-node.

The first truthy check yields a single cancelled event and returns, without yielding completed. Either way, a cancelled execution's compiled graph is dropped from the cache, so its execution_id can no longer be reused with execute(execution_id=...).

# typical wiring: a threading.Event flipped by whatever cancels the job
cancel_event = threading.Event()

for event in engine.execution.execute(spec=spec, cancel_check=cancel_event.is_set):
    if event["event"] == "cancelled":
        break
No cancel_check, no cancellation. When it's omitted, execute runs straight through to completed or failed; the check is only ever consulted if you pass one in.

validate(spec, bucket=None)

Iterator[dict] validate(spec: dict, bucket: str | None)

Checks a spec against the registry and sandbox without compiling or running it. bucket scopes the node registry the same way it does for execute, so a graph using bucket-specific custom node types must be validated with that same bucket to resolve them. Yields validating followed by either valid or failed.

Unlike execute's failed event, which only carries the single error that stopped compilation, validate walks the whole graph and, when the failure comes from node params, connection wiring, or schema inference, attaches an errors array to the failed event with one entry (node_id, node_type, message) per problem found, not just the first. Structural failures (unknown node type, bad connection reference, no entry point, a cycle) still short-circuit as a single error.

discard(execution_id)

None discard(execution_id: str)

Drops a compiled graph from the cache so it can no longer be reused with execute(execution_id=...). Called automatically on cancellation; can also be called directly to free a graph you know you won't re-run. Compiled graphs are also evicted automatically, oldest-used first, once more than max_cached_graphs (see build_engine, default 128) are held at once - so a long-idle execution_id can become invalid even without an explicit discard.

Data Resource

Manages the named internal resources that fetch_internal and push_internal nodes read from and write to. Accessible as engine.data_resource.

MethodParametersDescription
import_sourcekey, source_kind, source_params, bucket=None, overwrite=FalseReads from an external source (file, database, and so on) and saves the result under key.
listbucket=None, prefix=None, limit=None, offset=0Lists stored resource keys, optionally filtered by prefix and paged.
getkey, bucket=None, limit=100, offset=0Returns schema, row count, and a page of rows for a stored resource.
deletekey, bucket=NoneRemoves a stored resource.
existskey, bucket=NoneReturns a plain boolean, not an event stream.

Resources are scoped by an optional bucket, letting the same key coexist across separate namespaces.

Storage format and source_kind. Whatever format a resource was imported from, it is always persisted internally as Parquet; key should not include a file extension. For import_source, source_kind="file" accepts a source_params.format of "csv", "parquet", "arrow", or "json" (newline-delimited JSON) - the same reader used by fetch_csv/fetch_parquet/fetch_arrow, plus a "json" format that has no dedicated built-in fetch node. source_kind="database" takes the same dsn/table/query/partition_on/partition_num params as fetch_postgres.

Node Library

Registers custom node types on top of the built-in ones, so a graph can reference project-specific logic by name. Accessible as engine.node_library.

MethodParametersDescription
load_persistedbucket=NoneLoads previously registered custom types for a bucket into that bucket's live registry. execute and validate already call this internally before compiling, so it rarely needs to be called directly - mainly useful to warm a bucket's registry ahead of time.
register_transformname, expression, description="", bucket=NoneRegisters a reusable sandboxed expression as a new transform node type.
unregister_nodename, bucket=NoneRemoves a previously registered custom node type. Built-in types cannot be unregistered.
get_nodename, bucket=NoneReturns the definition of one custom node type.
describe_nodesbucket=NoneReturns a descriptive summary of every node type available to the parser.
list_nodesbucket=NoneReturns built-in type keys alongside full definitions of custom types.

Custom node types are looked up by the parser the same way built-in ones are, so once registered they can be used as any other type value in a graph spec - provided that graph is compiled with the same bucket the type was registered under (default bucket if omitted on both sides). A name is global to its bucket: it cannot collide with a built-in type or with another custom type in the same bucket, but the same name can be reused independently in a different bucket.

A node type produced by register_transform is not called with zero configuration: at graph-build time it still requires a columns param (list of column names), and applies expression to each of those columns independently, with the target column's own value bound to the identifier value (in place of the whole-row df used by filter/derive).
