Source and sink nodessourcesink

Sources start a branch by reading data in; sinks end a branch by writing data out. Both types read and write lazily.

schema. Every source node except fetch_internal accepts an optional schema param: an object mapping column name to Polars dtype name (the same format as cast's types, for example {"amount": "Float64"}). When set, it is used as-is for schema inference and validation instead of sampling the actual source, which is useful when the source isn't reachable yet at validation time or when inference would be expensive. It does not cast or affect the data read at execution time - only the schema the compiler assumes for downstream nodes.

fetch_internal is the one exception, and not by accident: it reads a resource the engine itself already wrote (via push_internal or import_source), stored internally as Parquet - a format that carries its own schema, so there's nothing to declare and nothing to sample remotely. The other five sources read something outside the engine's control (a file that may not exist yet, a bucket, a live database) where the schema either isn't knowable in advance or is expensive/impossible to check during validate, which is exactly what schema is for.
